# Instructions for specifications

- Read the specification standard in `docs/SPECIFICATION_STANDARD.md`.
- Use stable identifiers and consistent status values.
- State goals, non-goals, assumptions, constraints, and unresolved questions.
- Write requirements and acceptance criteria so they can be verified.
- Link specifications to related requirements, decisions, components, and tests.
- Do not silently change approved specifications to accommodate generated code.
- Record material changes and assess their downstream impact.
- Keep documents proportionate to the scope; avoid ceremony without engineering value.
- Mark draft, approved, implemented, and verified states accurately.
