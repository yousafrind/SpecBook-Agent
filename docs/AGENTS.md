# Instructions for project documentation

- Keep documentation consistent with the implementation and current project status.
- Label concepts, proposals, planned work, prototypes, and implemented capabilities accurately.
- Use stable terminology across documents. The canonical terms are **Engineering Knowledge Base**, **Implementation Knowledge Base**, **specification package**, **source of truth**, and **engineering lifecycle**.
- Explain the problem, decision, rationale, trade-offs, and consequences—not just the chosen technology.
- Prefer vendor-neutral concepts; describe Claude, NotebookLM, and other tools as adapters or initial tools unless a decision explicitly makes them dependencies.
- Use Mermaid for diagrams when it materially improves understanding.
- Link related documents and avoid copying large sections between documents.
- Update the README navigation when adding or renaming foundational documents.
- Do not present hypotheses as proven results. Identify how claims could be evaluated.
