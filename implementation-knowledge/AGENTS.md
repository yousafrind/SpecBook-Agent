# Instructions for implementation knowledge

- Derive descriptions from the actual repository and execution evidence.
- Record repository, branch, commit SHA, extraction timestamp, and tool version where available.
- Link summaries to source paths, symbols, schemas, contracts, tests, or observed runtime evidence.
- Distinguish static-code inference from verified runtime behaviour.
- Identify uncertainty, missing evidence, and extraction limitations.
- Never let generated documentation override source code, tests, configuration, or observed behaviour.
- Refresh affected records after relevant implementation changes.
- Avoid copying secrets, environment values, private data, or sensitive logs into the knowledge base.
- Mark generated artifacts as derived and rebuildable.
