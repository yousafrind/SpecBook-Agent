# Instructions for implementation work

- Read root instructions and the relevant approved specifications before coding.
- Inspect existing code, tests, dependencies, and local conventions before proposing changes.
- Make bounded, reviewable changes; avoid unrelated rewrites.
- Preserve established interfaces unless a reviewed specification change authorizes modification.
- Add or update tests for changed behaviour and relevant failure cases.
- Validate inputs and enforce authorization at trust boundaries.
- Avoid unnecessary dependencies and explain material additions.
- Never commit secrets, credentials, private data, or generated artifacts that should not be versioned.
- Run relevant checks and report actual outcomes; do not claim unrun checks passed.
- Update implementation documentation and traceability when behaviour or interfaces change.
