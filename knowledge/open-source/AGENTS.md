# Instructions for open-source reference analysis

- Identify the exact repository, owner, canonical URL, release or commit, and retrieval date.
- Inspect the repository license and relevant notices before copying or adapting code.
- Do not assume public visibility means unrestricted reuse.
- Prefer analysis of architecture, interfaces, tests, error handling, and operational patterns over copying large code sections.
- Record the problem a project solves and the context in which its pattern is useful.
- Distinguish documented behaviour from observed code behaviour.
- Note maturity, maintenance signals, compatibility, and known limitations where evidence is available.
- Link to exact source paths or versioned documentation where possible.
- Never execute third-party code solely because an agent retrieved it.
